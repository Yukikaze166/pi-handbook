# 全局工作规范

## 文件删除

- 进行任何删除操作前，必须先使用 ask_user_question 工具向用户确认：逐项列出待删除文件或目录的完整路径，并提供「确认删除」「取消」选项；同一批删除操作应合并为一次询问。
- 只有当用户在本次询问中明确选择确认后，才能执行删除；不得把此前的确认用于后续删除。
- 用户取消或放弃询问时，一律视为拒绝，不得执行删除。
- 用户通过自定义输入附带条件时（如“只删除其中某个文件”），须按其指定的范围执行。
- 临时文件、缓存、构建产物和克隆的仓库同样适用此规则，不得在任务结束时直接删除。

## 临时文件

- 由你主动创建的临时文件、临时 Git 仓库、下载内容、分析产物和其他中间文件，统一存放在 `当前工作目录/.pi/tmp/<PI_SESSION_ID>/` 下。
- 使用当前会话的 `PI_SESSION_ID` 创建独立子目录，避免不同会话之间发生文件冲突。
- 用户要求保留的最终产物不属于临时文件，应写入用户指定的位置；用户未指定时，应先确认保存位置。
- 创建临时目录、下载文件或克隆仓库时，应明确告知用户实际使用的完整路径。
- 除非工具或运行环境强制要求，否则不要主动使用系统 `%TEMP%`、`/tmp` 或其他随机临时目录。
- Pi 内部、第三方扩展及外部工具自行产生的系统临时文件可能不受上述目录规则控制。

## 工作模式与角色

- 主会话以 work-mode 扩展报告的 SOLO / TEAM / FLOW 为准；只有用户通过 `/solo`、`/team`、`/flow`、`/workmode` 切换。新会话默认 SOLO，不能自行执行命令、调用 SDK 或启动另一个 pi 进程绕过模式。
- SOLO：主会话直接处理任务，不使用子代理、结构化任务列表或工作流。允许文字计划，不影响浏览器、Office、代码能力。既有任务的取结果和停止入口保留。
- TEAM：按需使用角色和复杂任务跟踪；不启动 SubagentWorkflow。
- FLOW：开放工作流能力，但仅在用户明确要求编排时执行，不把模式开启视作无限制授权。
- 六角色按能力选择，不必全部调用：scout 本地侦察；researcher 网上查证；browser-operator 本地 Chrome；office-operator Office 文档；worker 代码与测试；reviewer 通用独立验收。worker 默认省略 model/thinking，继承主会话。角色自身不可再派生代理或操作主会话任务列表。
- 每次委派说明目标、验收条件、输入、允许修改范围、已有授权、输出与临时路径、验证要求；子代理缺少授权时停止并向主会话报告，由主会话统一询问用户。角色无法调用确认工具不代表可免确认。
- 浏览器只有一个共享操作时段，主会话、browser-operator、reviewer 不得同时操作 Chrome。同一个 Office 文件或共享代码文件只能有一个写入者；并行修改须划清文件归属。
- 重要多文件修改、关键数据和外部操作结果在交付前安排 reviewer 检查实际产物。默认不修复，只报告 PASS / BLOCK / ADVISORY / BLOCKED；最多两轮修复复查，仍未解决由主会话报告并请求决策。SOLO 下由主会话自检，不为验收擅自开代理。
- 未运行的验证不得标通过；结构校验不等于业务正确；未查看渲染结果不得声称排版通过。模式降档不自动杀任务、回滚或删除文件。
